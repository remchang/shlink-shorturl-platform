# Issue #4 自主功能③ 创建频率限制 + 测试与文档

**标签**：`自主功能` `测试` `文档`

## 用户价值

短链服务如果不限流，会被脚本刷爆数据库，也可能被拿去做钓鱼跳板的批量生成。
另外「同一 IP 60 秒内最多建 20 条」本身也是一个明确的滥用防护规则。

## 为什么是服务端限流而不是前端禁用按钮

前端禁用按钮挡不住直接 `curl` 的脚本。真正的限流必须服务端做。

## 验收条件

- [x] 同一 IP 在窗口内超过次数返回 429，并告诉用户还要等几秒
- [x] **非法请求也计数**（否则攻击者用一堆无效请求白嫖配额）
- [x] 不同 IP 互不影响
- [x] 窗口过去后自动恢复
- [x] 配置写了 0 或负数不会变成「完全不限」
- [x] 明确标注局限：进程内内存、重启清零、按 IP 限

## 测试设计要点

| 用例 | 断言 |
| --- | --- |
| `test_pinlv_xianzhi_fanhui_429` | 第 4 次返回 429 |
| `test_feifa_qingqiu_yie_ji_ru_xianzhi` | 两次非法请求后，合法请求也被 429 |
| `test_butong_ip_hubu_ganrao` | 换 IP 恢复可用 |
| `test_chuangkou_guo_hou_chongxin_fangxing` | sleep 后恢复 |
| `test_cishu_shangxian_zui_shao_wei_yi` | 配 0 时至少为 1 |

## 为什么限流写在参数校验之前

第一版写在校验之后，结果发一堆非法请求完全不消耗配额——
因为非法请求在校验那一步就 `return 400` 了，压根走不到限流。
改到最前面之后才有意义。
