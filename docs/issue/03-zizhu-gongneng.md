# Issue #3 自主功能① 二维码 + ② 短链有效期

**标签**：`自主功能`

## 用户价值

- **二维码**：报告和 PPT 里贴短链，读者要手打；二维码直接扫，体验差很多。
- **有效期**：临时分享的东西不该永久有效，过期就该失效。

## 为什么这算「自主功能」而不是「调用上游 API」

指导书明确要求：

> 若 Shlink 已内置该能力，必须在本人 Web 中增加新的规则、校验或交互，
> 并用 API 参数真实生效；不能只显示一个静态控件。

所以两项都加了**上游没有的规则**：

| 功能 | 上游有什么 | 本人新增什么 |
| --- | --- | --- |
| 二维码 | 没有 | 完整实现；且二维码内容用**短链**而非长链，保证扫码访问也进统计 |
| 有效期 | `validUntil` 字段 | **上限 365 天**的规则；非整数/负数/超上限各有不同提示 |

## 验收条件

- [x] 二维码能在界面预览并下载 PNG
- [x] 二维码内容是短链，不是长链（可由扫码后的统计验证）
- [x] 短码不存在时返回 404
- [x] 服务器缺 `qrcode` 库时返回可读提示，不是 500 堆栈
- [x] 有效期传 0 或空 = 永久
- [x] 有效期传 400 天被我们自己的校验拦下（**不会打到 Shlink**）
- [x] 自动化测试断言参数真的传给了 Shlink（`test_youxiaoqi_chuandao_kehuduan`）

## 用到的 API 字段

| 功能 | 字段 | 来源 |
| --- | --- | --- |
| 二维码 | `shortUrl` | `GET /rest/v3/short-urls/{shortCode}` |
| 有效期 | `validUntil`（ISO8601 UTC，`Z` 结尾） | `POST /rest/v3/short-urls` |

## 失败处理

| 情况 | 返回 | 提示 |
| --- | --- | --- |
| 短码不存在（二维码） | 404 | 没有找到短码 xxx |
| 缺 qrcode 库 | 500 | 服务器没装 qrcode 库，请 pip install qrcode pillow |
| 有效期非整数 | 400 | 有效期必须是整数天数 |
| 有效期为负 | 400 | 有效期不能是负数 |
| 有效期超上限 | 400 | 有效期最多 365 天（实验规则，防止建超长期短链） |
